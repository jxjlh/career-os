# 技能矩阵学习模块设计

## 目标

将技能矩阵从“技能等级列表”升级为可持续使用的技能学习工作区：用户可以把技能分为“已经会的技能”和“想学的技能”，进入单个技能查看 AI 学习建议、B 站资源、考核评分和学习计划，并通过进度可视化持续追踪结果。

本次改造保留现有 Render 服务、现有路由前缀和已有技能推荐/考核能力，不迁移网站，不改变其他模块的数据和页面。

## 页面结构

### 1. 技能矩阵总览

- 顶部保留技能矩阵可视化，展示当前等级、目标等级和整体完成度。
- 可视化下方放置两个平行排列的分类按钮：
  - `已经会的技能`
  - `想学的技能`
- 两个按钮控制下方技能卡片列表，不在同一列表中混排。
- “想学的技能”作为独立分类，新增技能默认进入该分类。
- 两个分类都提供添加技能、修改技能和删除技能能力。
- 技能从一个分类移动到另一个分类时，保留等级、计划、资源和考核记录。

### 2. 技能详情

点击技能卡片后展示详情区域；未选中技能时不显示等级管理、知识点、考核和计划编辑区。

详情区域包括：

- 技能名称、分类、描述、当前等级、目标等级和掌握百分比。
- 等级编辑：当前等级、目标等级、信心度和保存操作。
- AI 学习知识点：根据技能、当前等级和目标等级生成需要掌握的具体知识点，并支持刷新。
- B 站学习资源：只使用 B 站搜索结果，展示标题、简介、作者/来源、链接和收藏操作。
- AI 考核：根据当前技能知识点生成题目；用户提交答案后显示分数、反馈、薄弱知识点和下一步建议。
- 学习计划：AI 生成周计划，用户可以添加、修改、删除计划，并标记计划完成。

“已经会的技能”仍然可以进入详情页进行等级管理、复习资源和考核，但默认不自动生成学习计划；用户主动生成时仍可创建计划。

### 3. 学习计划可视化

- 显示本周计划总数、已完成数量、完成率和预计学习分钟数。
- 按日期显示每日任务分布。
- 显示技能掌握进度趋势和最近考核分数。
- 计划状态变化后同步刷新统计和图表。

## 后端设计

### 技能状态

在用户技能关系中保存技能归类状态，取值为 `mastered` 或 `learning`。分类接口返回分类后的技能列表；新增、编辑、删除和移动操作只作用于当前用户的技能关系。

已有技能等级字段继续使用，避免破坏现有技能矩阵、入门流程和计划关联。

### 技能详情接口

增加或整理以下能力：

- 获取单个技能详情及学习统计。
- 生成技能知识点。
- 获取 B 站资源。
- 生成并保存技能周计划。
- 对技能计划执行增删改、完成/取消完成。
- 获取技能计划和进度统计。
- 保存考核记录和评分结果。

接口沿用现有 `/api/v1/skills` 路由体系，所有接口继续要求当前用户认证。

### B 站资源搜索

- 技能页资源搜索固定使用 B 站 provider，不再把通用搜索引擎结果混入技能资源区域。
- 搜索词由技能名、知识点和用户输入组合生成。
- 当 B 站没有结果时，明确显示空结果，不回退到其他来源。
- 收藏仍复用现有资源库收藏接口。

### 默认分类

- 保留现有默认技能种子，不额外新增名为 `相学` 的技能。
- 新增技能默认归入当前用户的“想学的技能”分类。
- 已有用户数据不被重置。

## 前端交互

- 详情内容通过当前选中技能 ID 加载，点击不同技能时清理上一个技能的临时考核答案和搜索结果。
- 添加技能只要求技能名称，分类、描述和默认目标等级使用简化默认值；创建后进入“想学的技能”。
- 删除技能需要二次确认。
- AI 请求和保存操作显示加载状态、成功提示和失败提示。
- 计划编辑使用轻量表单，不增加不必要字段。
- 移动分类使用单个按钮或菜单操作，操作完成后保持当前技能选中状态。

## 数据兼容与部署

- 如需新增数据库字段或表，提供 Alembic migration，并在本地测试中覆盖升级后的行为。
- 前端构建产物继续同步到 `apps/api/static`，保证当前 Render API 服务可以直接提供更新后的页面。
- 不改变现有生产域名，不迁移到其他平台。

## 验收标准

1. `/skills/` 顶部能看到矩阵可视化和两个平行分类按钮。
2. “想学的技能”分类可以添加、修改、删除技能。
3. 同一技能可以在“已经会”和“想学”之间移动，等级和学习数据不丢失。
4. 未点击技能前不显示技能等级管理、AI 知识点、考核和计划编辑内容。
5. 点击技能后能看到具体知识点、B 站搜索结果、AI 考核评分和学习计划。
6. 学习计划可以由 AI 生成，也可以手动添加、修改、删除和完成。
7. 技能详情能够展示计划完成率、每日任务和技能进度图表。
8. 前端 typecheck、lint、build 和后端测试通过。
9. 新提交推送到 GitHub 的 `main`/`master`，Render 原域名线上 `/skills/` 页面确认更新。
